# hiddenarena

A blind, head-to-head benchmark of coding harnesses, built on
[harness-interface](https://github.com/mrcloudchase/harness-interface) v1.0.2 as a Python library (no server).

```bash
uv sync
hiddenarena compare smoke --model deepseek/deepseek-chat      # every harness, one model
hiddenarena defaults smoke                                    # every harness, its own default model
```

Each command is the whole pipeline (probe, run, judge, report) and resumes if you give it the same `--run-id`.

## Two modes, never mixed

| | Question | Results | Report |
|---|---|---|---|
| `compare <benchmark> --model p/m` | which harness is best on one model? | `results/compare/<p>/<m>/<benchmark>/<run-id>/` | `reports/compare/<p>/<m>/<benchmark>.md` |
| `defaults <benchmark>` | which vendor's default stack is best? | `results/defaults/<benchmark>/<run-id>/` | `reports/defaults/<benchmark>.md` |

Options: `--harnesses a,b|all`, `--tasks N`, `--repeat K` (default 3), `--workers W`, `--run-id`, `--judges p/m,p/m`,
`--judge-harness H`, and `--no-relay` (compare only).

Before a benchmark every harness takes one trivial turn on the model. One that fails is *unsupported* for it:
skipped, listed in the report, never scored. A harness is pointed at the model by keeping its API shape
(anthropic or openai) and swapping its provider for the vendor's endpoint of that shape (`hiddenarena/catalog.py`).
Keys come from the environment: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, `GEMINI_API_KEY`.

## A benchmark is a folder

`benchmarks/<name>/benchmark.py` exposes

- `tasks()`: yields `Task(id, instruction, files)`. A task never names its benchmark, dataset or any harness.
- `deliverables(task)`: glob patterns of the files that make up the submission. Only these are ever judged.
- `judges(task)`: `Deterministic(check)`, `Model(rubric)` and `Exercise(rubric)`, in order.

`hidden/` and `calibration/` beside it never enter a contestant's workspace; a task whose input repeats anything in them
is a finding. A dataset under another licence stays outside the repo (see `benchmarks/humaneval`).

| Benchmark | Judges | |
|---|---|---|
| `smoke` | hidden pytest tests | five small Python tasks |
| `readme` | names-the-API check, model panel (+ pairwise) | write a README for a codebase; calibrated |
| `todoapi` | compiles, held-out harness judge | a JSON API that must be run; calibrated |
| `humaneval` | hidden tests | HumanEval, read from `HUMANEVAL_PATH` (MIT, github.com/openai/human-eval) |

## Blinding

Judges see the work, never the worker. This is enforced in code and tested (`tests/test_blinding.py`).

1. **Submissions, not transcripts.** After a turn only files matching `deliverables(task)` are copied into a fresh
   submission directory. Output, logs, `.home/`, the record, instruction files (`AGENTS.md`, `CLAUDE.md`, `QWEN.md`),
   dotfiles (`.aider*`), binaries, links out of the workspace and everything else stay behind. Workspaces live at neutral
   paths (no harness, model or benchmark in them).
2. **Scrubbing.** Harness names, CLI names, providers, model names, co-author trailers and "generated by" lines are
   redacted. The list is built from the harness folders, the provider catalog and the models in use. Redactions are counted
   per submission and reported.
3. **Opaque ids.** Each submission is `S-xxxxxx`. `sealed/map.json` maps ids to (harness, model, task, repeat); it can be read
   (`RunDir.sealed()`) only after judging is marked finished, and the judging module never touches the run records.
4. **Shuffling.** Submissions are judged in random order; pairs are judged in both orders.
5. **Blindness check.** `hiddenarena blindcheck <run-dir>` asks each model judge to guess the harness; better than chance by a
   one-sided binomial test (p < 0.05) flags that benchmark's judged scores in the report.

## Judging

1. **Deterministic**: hidden tests, run on the host on the submission directory. No calibration needed.
2. **Model judge**: a plain `httpx` call at temperature 0 with the task, the rubric and the scrubbed submission; a score and a
   reason per rubric item. A panel of at least two families, fixed per run (saved in `config.json`); in compare mode none is
   the compared model's family. The panel median is the score and each judge's own score is shown.
3. **Harness judge**: a held-out harness (never a contestant), in its own sandbox, in a fresh workspace holding only the
   submission, the task and the rubric; it writes `verdict.json`. One run per judge model, under the panel rules.

`hiddenarena calibrate <benchmark>` measures each judge's agreement (correlation) with the human scores in `calibration/`.
Judged scores are reported only if every judge reaches the benchmark's threshold.

## Integrity

A run that breaks a rule is a finding: listed, never scored. Provider refusals (auth, quota, rate limit) are runner errors:
retried, then listed, not held against the harness. A timeout is graded as it stands. In compare mode a recording relay sits
between the harnesses and the provider and records the `model` of every call; a run that called another model is a finding.
See `hiddenarena/relay.py` for how and for its limits.

## Layout

```
hiddenarena/   catalog  benchmark  store  turns  arena  submission  scrub  models  judging  exercise
               calibrate  blindcheck  report  relay  checks  pool  cli      (one job each)
benchmarks/    smoke  readme  todoapi  humaneval
tests/         fake harness folders on harness-interface's LocalRuntime
reports/       the rendered reports, indexed by reports/README.md
results/       raw records, verdicts, submissions, sealed maps (not committed)
```

```bash
uv run pytest        # no Docker or keys needed
```
